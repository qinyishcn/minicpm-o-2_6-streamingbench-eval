# 100% 丢包准确率核查：全零特征与纯文本对照

2026-10-09。沿用相同 125 道题、Q4_K_M 权重、Windows Vulkan b11516、官方选择题提示词及贪心解码。
新增三个条件共 375 次真实模型回答。所有题目独立清空语言 KV 缓存，按固定散列顺序打乱提问顺序。

| 条件 | 答对/125 | 准确率 |
|---|---:|---:|
| 原始单帧、无丢包 | 98 | 78.4% |
| 原始四帧、无丢包 | 100 | 80.0% |
| 全新进程、单帧特征直接构造为全零 | 73 | 58.4% |
| 完全移除图像及视觉特征，只保留原题目和选项提示词 | 70 | 56.0% |
| 纯文本，逐题循环轮换选项位置并同步映射答案 | 70 | 56.0% |
| 固定选择最多的标准答案 D，无模型推理 | 44 | 35.2% |

## 已核查的事实

- 原来两个 100% 丢包条件的全部 250 条记录，接收端特征 SHA-256 都等于相应长度全零缓冲区的 SHA-256，所有包均丢失，所有特征字节均置零。
- 新进程的 125 个单帧全零特征答案，以及完整首步 logits SHA-256，全部与原 100% 丢包实验一致。该对照从未调用视觉编码推理，直接分配全零字节；未先运行任何正常视觉问答。
- 代码只用题目和四个选项构造提示词。标准答案不进入模型输入；新对照仅在全部回答生成后读取 label 计算正确率。全零推理元数据也没有 question_id 或帧文件名供模型读取。
- 纯文本条件没有图像标记或视觉 embedding。仍保留原提示词中关于视频帧的说明，以尽量保持其余指令不变；它与保留图像标记及全零 embedding 的条件并不完全相同。
- 选项轮换逐题采用由 question_id 的 SHA-256 确定的 1–3 位循环位移，重新标记 A–D，评分映射回原选项。只是一次固定轮换对照，未做多次随机重复。
- 轮换前后总准确率相同，但 34/125 题所选的选项内容发生变化。因此不能据相同总分断言模型对选项顺序不敏感。
- 原单帧与四帧全零条件都答对 73 题，但只有 115/125 题给出相同字母答案。相同准确率不等于逐题输出完全一致。

## 解释与结论边界

这组题在完全没有视频内容的情况下仍可获得 56.0%，所以 100% 丢包的 58.4% 有实测支持，并非只能由特征残留或答案泄漏解释。
题目措辞、选项可排除性及模型的语言知识可能提供大量线索。例如：

> Why does the player wearing the number nine red and blue jersey celebrate?

其选项为 saved a goal / received a pass / scored a goal / won a free kick。没有视频也能倾向于“进球”。
在因果推理题上，纯文本答对 5/5；动作感知题为 14/18。这是小样本描述，不能推广到整个 StreamingBench。

应把“网络损伤后的任务准确率”和“依赖视觉信息的能力”分开解释。当前单帧无损比纯文本高 22.4 个百分点，四帧高 24.0 个百分点；
这些是本子集的总分差，不是可独立分解的视觉贡献，也不是视觉必需题目上的抗丢包分数。
后续 Testbed 报告应同时列出纯文本/全零基线及逐题变化，不能把 58.4% 的残余准确率称为视觉容错性能。

这些控制支持语言线索解释，但不能区分通用知识、数据集语言偏差和可能的训练集重合；本次没有审计模型训练数据。
